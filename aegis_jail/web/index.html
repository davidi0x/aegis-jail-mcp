The permission model

Boundaries

Agent freedom inside a deliberate, limited workspace.

Big power
Small permissions

An enforceable boundary that lets your agent work while your system, data and network stay under your control. The operating system enforces it (sandbox), not the AI's good behavior.

Project copy

Runs on a copy of your project. You review the changes before they reach your files.

Network allowlist

Outbound access only to the hosts a profile lists. aegis probe shows what really holds.

Private by default

Your home folder, SSH and cloud keys, tokens and .env files stay out of reach unless you expose them.

Human in control

aegis diff and aegis apply decide what reaches your project. Risky files need an explicit yes.

This is a model of how Aegis Jail MCP enforces permissions, not a live certificate. Run aegis probe to test it on this machine.

Runs in the background

Autopilot

Decide what Aegis does on its own and which agent handles what it finds.

What Autopilot does

A responder can contain, never approve

Allowed actions
  • Jail an MCP server with full rights
  • Discard a run that tripped a wire
  • Read events and run a scan
  • Mark what it handled, with a note
Forbidden actions
  • Re-trust a changed or poisoned tool
  • Apply changes to your project
  • Grant itself new permissions
  • Use any tool outside Aegis

Start Autopilot at login

Run this once to keep Autopilot running in the background whenever you log in. Remove it any time with aegis watch uninstall

$ aegis watch install

1Quick install

Install Aegis

Python 3.10 or newer, no dependencies.

$ pip install git+https://github.com/davidi0x/aegis-jail-mcp
# or with pipx
$ pipx install git+https://github.com/davidi0x/aegis-jail-mcp
2Your sandbox

One backend per system

Aegis picks the native sandbox of your operating system.

3Core commands

Use the CLI

Start a project, run a task, review it, apply it.

$ aegis init   # set up
$ aegis run    # sandboxed task
$ aegis diff   # review
$ aegis apply  # accept
4Create a task

Add a profile and a task

A profile says what the agent may reach. A task says what it should do and how to check it.

.aegis/profiles/web.json
{
  "aegis": 1,
  "name": "web",
  "agent": "claude-code",
  "grants": [{
    "id": "npm", "kind": "net",
    "domains": ["registry.npmjs.org"],
    "phase": "setup"
  }]
}
.aegis/task.json
{
  "name": "fix-tests",
  "agent": "claude-code",
  "prompt": "Fix the failing test",
  "setup": "npm ci",
  "verify": "npm test"
}
